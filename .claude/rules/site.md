# site

Paths below are relative to `site/`.

## Checks

From the repository root: `pnpm -C site lint`, `pnpm -C site typecheck`,
`pnpm -C site --filter @aubesonore/frontend test --run` and
`pnpm -C site --filter @aubesonore/backend test`. On a fresh worktree, build the shared types first:
`pnpm -C site turbo build --filter=@aubesonore/shared-types`; without them lint reports errors
everywhere.

## Workflow

- Named exports rather than default ones.
- A visible change is tried at 1280 and 390 px wide on the local stack (`pnpm -C site stack`) before
  its merge.
- Vitest without `--run` watches.
- `db:push` reads `DATABASE_URL`, else `.env`: export the test database's first, or it syncs
  `schema.ts` onto the database `.env` names.
- Frontend i18n messages (`apps/frontend/src/paraglide/`) are generated by `compile:i18n`, not
  committed: a bare `tsc` or `eslint` in `apps/frontend` fails on missing imports, the package
  scripts compile them first.

## Deployment

- Leave `schema.ts` alone in a PR that changes no schema: the deploy compares the file and stops on
  any change without its own migration, a comment included. When a comment there must follow the
  code, acknowledge right after the merge (README « Déploiement »).
- Check a compose change with `docker compose config` against a production-like `.env` before
  merging. AzuraCast keeps its own compose, separate from this one: its updater manages it, and a
  site deploy must leave the radio running.
- A restore is rehearsed into a throwaway database before production:
  `docker exec -i aubesonore-db pg_restore -U aubesonore -d <db> < <dump>`.
- `db:push` can drop columns and `drizzle-kit generate` cannot work (no snapshot meta): migrations
  are hand-written idempotent SQL (`IF NOT EXISTS` / `IF EXISTS`).

## Artist pages

Product rules are in `../docs/vision.md`; the page always answers (§4.6), each source allowed to fail
on its own.

- Before touching artist identity, read vision §4.4 and §5: an ISRC counts only for the played track
  and is checked against title and name; binding by name alone or by Deezer's API doesn't identify.
  Slugs: `services/artistSlugs.ts`.
- A page exists for every artist Musilogy knows, not for a typed name: `/api/artist/resolve` is
  public, and a page for any typed name would let anyone publish text under aubesonore.fr. An MBID
  the dump does not hold is a 404; while Musilogy is not loaded, 503. Indexing threshold:
  `discoveredArtists.ts`.
- After a deploy that changes identity, Victor runs the catch-up: `/artists-resolve`.
- A Commons file without a licence is no photo.
- No source, licence or tool is named on a listener's page (vision §1.2); credits live on the legal
  page. Exceptions: the Wikipedia opening links its article (CC BY-SA), and a photo's credit is shown
  behind a small © on the portrait (CC BY-SA §4c).
- `og:image` is restricted to the Cover Art Archive: a link preview could not carry a Commons photo's
  credit.
- Covers fade in (`useFadeIn`) only when they mount still loading: not hidden before the script runs,
  not on a server-drawn priority image, not on an image whose source changes.

## Musilogy data

`musilogyService` calls only the SQL functions of `../musilogy/docs/conception.md` §4, not the tables.

- A section not loaded yet is `null`, not empty. A function Postgres does not know (`42883`, or the
  schema missing) makes its section `null` and the page leaves it out; the card and the search answer
  503, and the search says Musilogy is not available rather than « reloading » (a load may not come).
- An end date is shown only when declared, not inferred from a last album; a start read from the
  first album says so.
- Every artist link goes through `pagePathOf`. A section with nothing in it is left out. A single
  year reads alone (« 1992 »), not « de 1992 à 1992 ».
- `MusilogyTimeline`: the owner rejected a light band behind the rows. The artist's own row is
  `aria-hidden` (the page header says its years).

## Casting

- Chromecast uses AubeSonore's Custom Web Receiver so the TV's title and cover follow the track on
  air; the Default Media Receiver can't.
- `cast/receiver.html` plays the station as a LIVE stream without Pause, because resuming plays the
  buffer behind the antenna.
- One Diffuser button (`CastControl`) for Cast and AirPlay, rather than Google's
  `<google-cast-launcher>`, which hides itself without a device and knows no AirPlay.
- Test on the devices registered in the Cast console before publishing the app: publishing makes it
  reachable from every Cast device.

## Security

The app has no URL guard: a route that must fetch a user-supplied URL needs one first, blocking
private IPv4/IPv6 and link-local (`169.254.0.0/16` = cloud metadata) and enforcing `https` in prod.

## Track links and YouTube

- Track links come from each platform's API; Odesli's keyless API is closed. A kept track's Deezer
  link comes from its ISRC (`/track/isrc:`), which finds the recording the antenna plays; the title
  search often picks another version and is only the fallback.
- YouTube (`youtubeService`, `youtubeLinks`): a stored link is a search until an Art Track is
  verified. A result counts only when its « Title · Artist » line is the kept track (feat. and
  remaster set aside).
- YouTube's limits are load-bearing ([quota costs](https://developers.google.com/youtube/v3/determine_quota_cost)):
  search.list has its own small daily bucket. API data must be refreshed or deleted within 30 days
  (Developer Policies III.E.4.d), so a link older than that is not served. Keep `YOUTUBE_API_KEY` out
  of logs, including a network error's URL.

## Scaling

Caches and rate-limit buckets are in-process on purpose (`TtlCache` behind the `CacheStore<V>` surface
a Redis store would keep). Tiers and their triggers are in `docs/scaling-roadmap.md`: wait for a
tier's trigger before building it.
